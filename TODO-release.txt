НУЖНО СДЕЛАТЬ ВЛАДЕЛЬЦУ ПРОЕКТА (без этого в production не запускать)
---------------------------------------------------------------------

[!] 1. Постоянная база данных
       Без Supabase/PostgreSQL сервер хранит данные в файле data/tedcloud-store.json
       (см. пункт «Сделано»). Для production с несколькими пользователями и
       резервным копированием нужна настоящая БД:
         - создать проект Supabase (или PostgreSQL);
         - применить миграции из db/migrations/ (001 → 004);
         - задать переменные NEXT_PUBLIC_SUPABASE_URL и SUPABASE_SERVICE_ROLE_KEY.
       Когда БД настроена, файловое хранилище автоматически отключается.

[!] 2. Секрет сессий
       Задать TEDCLOUD_SESSION_SECRET (не короче 32 символов) на сервере.
       Генерация: node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
       Без него сервер в production-режиме откажется выдавать сессии.
       Смена секрета разлогинит всех пользователей.

[!] 3. Ключ ИИ (по желанию)
       Задать GEMINI_API_KEY. Без ключа ассистент работает на встроенной аналитике.
       Проверить имя модели в api/db.ts ("gemini-3.8-flash") — актуально ли оно
       для вашего аккаунта Google AI.

Запуск в production:
       npm ci
       npm run build
       npm start            (слушает PORT, по умолчанию 3000)
